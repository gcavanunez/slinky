Share invocation choices through profiles. `slinky autoinvoke <skill> off --profile fleet` makes a skill manual-only on every machine following `fleet`, `on` explicitly allows automatic invocation, and `inherit` removes the profile's choice. Choices live in a new optional `autoinvoke` field in `skills.manifest.json`, so they travel with `save`, `push`, and `fleet sync` like profile membership does. A machine's own `slinky autoinvoke` setting still wins, and `slinky profile promote` now moves those settings into the profile along with enable and disable changes. `status` labels a profile's choice `(profile)` and `profile list` shows each profile's choices. A choice made on a machine or a profile now also sets Claude Code's `disable-model-invocation` in the installed copy, not only OpenCode's `metadata.opencode/autoinvoke`; skills without one keep their author's Claude Code flag, so on upgrade only skills that already have a `slinky autoinvoke` setting are rewritten, on the next sync. The field is left out when no profile has a choice; a manifest that has one does not load on older Slinky releases, so upgrade every machine before setting the first.
